# Этот форк: DeepSeek V4 Flash 0731, ускоренный

Это форк [PolyStrata](https://github.com/VecSzn/PolyStrata) (самого, в свою очередь, построенного
на [Strata](https://github.com/Niko1221/Strata) от Niko1221), в который добавлена цепочка
экспериментальных оптимизаций для более быстрого запуска
[DeepSeek V4 Flash 0731](https://huggingface.co/unsloth/DeepSeek-V4-Flash-0731-GGUF)
на одной видеокарте NVIDIA. Все изменения — в ветке `base`.

Цепочка состоит из 8 патчей плюс слоя file-reads / read-heat / attend-batch и ядра `hc_mix`
в виде маленького GEMM. На тестовой рабочей станции она писала со скоростью **247 токенов/с**
при контексте 11k, с холодного старта. Токен — это примерно ¾ слова.

## Цепочка патчей

Каждый патч — самодостаточный файл в корне репозитория (`*.patch`). Они применяются друг на друга
по порядку; поздние зависят от ранних.

1. **q8_0 кэш ключей и значений** (`deepseek4_q8_0_kv_cache.patch`) — кэш внимания для DeepSeek V4
   хранится в формате q8_0 (8 бит) вместо fp16. Это вдвое сокращает объём кэша KV в VRAM,
   оставляя кэшу экспертов больше места на карте.

2. **Быстрая q8_0-деквантизация префилла** (`prefill_q8_fast_dequant.patch`) — упакованная
   деквантизация строки ключей в ядре внимания: один выбор масштаба на слово и упаковка half2
   сокращают цикл подготовки ключей примерно вдвое. Чтение ключей окна — это и есть время
   внимания префилла.

3. **16 голов на блок** (`group_heads_16.patch`) — ядро внимания берёт 16 голов на блок вместо 8.
   Одна подготовленная строка ключей обслуживает вдвое больше голов, прежде чем её отбрасывают,
   сокращая трафик ключей внимания префилла вдвое. Для DeepSeek V4 (64 головы) токен занимает
   4 блока вместо 8.

4. **Многоблочные строки внимания** (`multichunk_attend_rows.patch`) — пакет префилла больше
   65535 строк (предел grid.y в CUDA) обслуживается запусками по столько-то строк на хосте,
   строки q, sel, out и `at` его токенов идут за предыдущим куском. Работает одинаково для q8_0
   и fp16.

5. **Оценки индексатора на тензорных ядрах** (`idx_score_mma.patch`) — оценки индексатора
   вычисляются инструкциями `mma.sync` на тензорных ядрах, где карта их поддерживает (вычислительная
   способность 8 и новее), вместо скалярного ядра. Блок оценивает 16 токенов против 128 сжатых строк.

6. **Асинхронное перекрытие префилла** (`async_overlap_fixed.patch`) — куски чтения длинного
   промпта перекрываются: работа на хосте и загрузка следующего куска идут рядом с последними
   слоями предыдущего, через событие, а не когда карта простаивает между кусками. Управляется
   флагом `--read-overlap`.

7. **Кэш разговора, размер из свободной RAM** (`conversation_cache_mib_auto.patch`) —
   `--conversation-cache-mib auto` подбирает размер кэша разговора из свободной RAM после загрузки
   модели: 40% от того, что осталось выше порога парковки, максимум 8192 МиБ, шагами по 256.
   Фиксированные 8 ГиБ на ПК, чья RAM уже заполнена файлом модели, выталкивали этот файл из кэша.

8. **Ключ конфигурации кэша разговора** (`conversation_cache_config_key.patch`) — ключ
   `conversation_cache` в конфиге сервера включает кэш разговора: `"auto"` или `true` подбирает
   размер из свободной RAM, число означает столько-то МиБ. `--conversation-cache-mib` в аргументах
   побеждает ключ.

## Слой базы

Поверх патчей коммит `base` добавляет три возможности движка, каждая со своим флагом:

- **file-reads** (`--file-reads`) — маршрутизированные эксперты читаются из своего файла по позиции
  (`pread` / `ReadFile`) в закреплённые буферы, а не копируются через отображаемый файл, чьи
  отсутствующие страницы приходят по одной ошибке за раз, когда RAM вплотную заполнена моделью.
  Включено по умолчанию.
- **read-heat** (`--read-heat`) — то, куда маршрутизирует промпт, прогревает кэш экспертов:
  буфер стадии держит то, что промпт читает чаще всего, а после чтения кэш принимает своих самых
  занятых экспертов. Включено по умолчанию.
- **attend-batch** (`--attend-batch`) — внимание DeepSeek V4 берёт два токена на блок, объединение
  их окон ключей подготавливается один раз. Включено по умолчанию.

И финальный коммит заменяет смешение `hc_pre` и `hc_head` маленьким GEMM для пакетов (блок из
четырёх строк вычисляет все выходы), оставляя старое ядро для декодирования.

## Флаги

Цепочка добавляет движку такие флаги командной строки:

| флаг | что делает | по умолчанию |
| --- | --- | --- |
| `--read-overlap N` | 1: следующий кусок чтения длинного промпта перекрывает последние слои предыдущего; 0: карта простаивает между кусками | 1 |
| `--file-reads N` | 1: маршрутизированные эксперты читаются из файла по позиции в закреплённые буферы; 0: копирование через отображение | 1 |
| `--read-heat N` | 1: то, куда маршрутизирует промпт, прогревает кэш экспертов; 0: чтение ничего не меняет | 1 |
| `--attend-batch N` | 1: внимание DeepSeek V4 берёт два токена на блок; 0: токен на блок | 1 |
| `--group-heads N` | головы, которые берёт блок внимания: 16 или 8 | 16 |
| `--q8-dequant N` | с `--kv q8_0`: 1 = упакованная деквантизация строки ключей, 0 = по одному значению | 1 |
| `--attend-chunks N` | 1: пакет больше 65535 строк обслуживается запусками по столько-то; 0: один запуск | 1 |
| `--idx-mma N` | оценки индексатора на тензорных ядрах, где карта их имеет. 2, по умолчанию: mma и на decode-окнах, и на промпт-батчах - скалярное скор-ядро упёрлось в shared memory (запрос и ключ оба из shared, 8 байт на умножение), его сегмент стоит 17 мс на вызов при промпте 26k против 1.3 у mma (score+sel в [att]); 1: mma только на формах decode-окон; 0: скалярное ядро всюду. Скоры mma - половинки, не бит-в-бит: почти равные выборы могут разойтись | 2 |
| `--idx-fused N` | 1: скор и select индексатора промпт-батча в одном ядре, скоры держатся в shared memory карты и не пишутся в HBM, один запуск на весь вызов (блок на токен; нужно 256 токенов и больше, и каждый токен до позиции 32k, иначе вызов остаётся на двухъядерном пути). Скоры бит-в-бит совпадают со скалярным ядром, выборы не меняются; 0: ядра скора и select'а, батчируемые по скор-буферу, score(батч k+1) beside select(батч k). Оставлено как research и выключено: цена фазы - вычисления скорера, а не HBM-оборот скоров (0.4 из 17 мс), и mma-скорер берёт те же вычисления в 13 раз быстрее - fused ядро с его скалярным циклом доминируется `--idx-mma 2` | 0 (выкл) |
| `--ram-experts-mib N` | RAM-пул на столько МиБ, держащий самых используемых экспертов вне VRAM целиком в собственной памяти процесса (LRU целых экспертов; чтения удержанного эксперта перестают трогать page cache; decode-swap-ы тоже читают через пул — промах оседает в нём, и следующий запрос повышается из RAM скоростью memcpy, который держит файлы модели лишь пока тому нет других претендентов). 0 = через page cache, как раньше | 0 (выкл) |
| `--vram-pool` | вся свободная VRAM карты запрашивается один раз при загрузке (за вычетом резерва) и раздаётся растущим картам из пула хендлов — экспертный кэш и кэши внимания перестают дёргать драйвер на каждой стадии. Нужны VMM, растущие кэши внимания и одна карта | выкл |
| `--resident-topk N` | decode-окно вычисляет только N тяжелейших из маршрутизированных экспертов токена, где бы они ни жили (включая кэш в VRAM), top-1 всегда жив, оставшиеся веса перенормируются по правилам модели; prefill остаётся точным. Меняет ответы (кап из Maya Turbo; DSv4 маршрутизирует 6) | 0 (выкл) |
| `--prefetch-k N` | упреждающее чтение N самых вероятных экспертов следующего MoE-слоя каждого токена — догадка по входу текущего слоя, пока карта считает attention следующего; промахи идут в пул --ram-experts-mib. Только decode/verify-окна (до 16 токенов); требует --ram-experts-mib | 0 (выкл) |
| `--expert-mma N` | 1: произведения экспертов Q3_K (gate/up и down, если он тоже Q3_K) на собственном тензорном ядре форка: строки в простой per-32 int8, коды во f16-фрагментах mma; 0: generic mmq llama.cpp. Нужна sm_80+; остальные типы остаются на generic mmq | 0 (выкл) |
| `--cpu-tiled N` | 1: gate/up экспертов на CPU — через tiled-ядра K-квантов (раскладка по регистрам, AVX-512/VNNI); 0: прежний построчный путь vec_dot. Tiled ведает Q2_K, остальные типы весов сами идут через vec_dot | 1 |
| `--conversation-cache-mib` | `auto`: 40% свободной RAM после загрузки, выше порога, максимум 8192; число: столько-то МиБ | 0 (выкл) |

Кэш ключей и значений q8_0 включается для каждой модели существующим флагом движка `--kv q8_0`,
который этот форк распространяет на DeepSeek V4 (раньше он был только для qwen35moe).

## Переключатели окружения (движок читает их из env-блока конфига)

| переключатель | что делает | по умолчанию |
| --- | --- | --- |
| `STRATA_POLY_STAGE_SPEC=<M>` | guess-reader стагинга: пока карта считает батчи слоя j, поток осаждает весь некешевый набор экспертов слоя j+1 в пул --ram-experts-mib (позиционные чтения). Стагинг следующего слоя берёт экспертов из RAM скоростью memcpy вместо fault'ов. Включён всегда при --ram-experts-mib; значение ограничивает кандидатов на слой (256 покрывает слой из 256 экспертов) | вкл, 256 |
| `STRATA_POLY_SCORE_CONTEXT=<N>` | stride скоров индексера покрывает N/4+1 записей вместо max_context/4+1. Промпт 26k токенов требует stride 6501, а не 33193 — HBM трафик тензора скоров падает пропорционально. Ставить на ожидаемую длину промпта в токенах | max_context |
| `STRATA_POLY_SCORE_MIB=<N>` | бюджет буфера скоров индексера в МиБ: больший бюджет вмещает больше токенов на запуск, меньше запусков, ровнее чтение | 128 |
| `STRATA_POLY_STAGE2_DEBUG=1` | печатает время копирования каждого раунда стагинга, разбивку route/card/copies каждого слоя и attention-фазу каждого префилл-батча (`[att] il=.. qkv .., squeeze .., idx .., score+sel .., attend .. ms` - время GPU половины q/kv, компрессора, подготовки индексера, скора+select индексера и самого attend; CUDA-события, только префилл-батчи) в stderr | выкл |

Стагинг читает позиционно (pread) вместо memcpy через mapping: ровный канал, который состояние
page cache не гнёт. Прогреватель mapping'а (mapper) не стартует, когда guess-reader стагинга
работает: позиционные чтения guess-reader'а греют page cache ровно там, куда маршрутизирует
чтение, beside осаждения пула — проход всего файла beside него только драл диск.

Скор и select индексера пайплайнятся через два stream'а, когда в промпт-батче больше одного
батча скоров: score(батч k+1) на indexer'ном stream'е идёт beside select(батч k) на основном —
score-ядро memory-bound, select compute-light, они делят GPU. Каждый select ждёт свой батч
скоров через event; attend ниже ждёт все select'ы на основном stream'е. Однобатчевые вызовы
держат старый односрочный путь.

mma-скорер индексера работает только на формах decode-окон (n ≤ 16 токенов, +17% decode):
промпт-батчи из 6500 токенов берут scalar dp4a-скорер, с которым они выигрывают (−8% чтения).

## Вердикты живых проверок (DeepSeek V4 Flash 0731, одна RTX 4080 SUPER, ноябрь 2026)

- **`--idx-mma 2` — принят, по умолчанию.** Вердикт тайминга [att]: рост attention-фазы с
  контекстом весь в сегменте score+sel (17 мс на ratio-4 вызов при промпте 26k, скалярный скорер
  упёрся в shared memory - два загрузки на умножение), а у mma сегмент 1.3 мс - в тринадцать раз
  меньше, 9 с из 98 с префилла. Прежние 8 процентов проигрыша на префилле не повторились. Скоры
  mma - половинки, почти равные выборы могут отличаться от скалярных.
- **`--ram-experts-mib 6144` — принят.** Качество нейтрально (батарея из десяти промптов на
  temperature 0 отвечает попунктно идентично чистому прогону; self-check пула 387/0, одним
  куском значит без рваных слотов), decode-свип ставит 6144 выше 2048, на длинных разговорах
  попадания 64.6%.
- **`--vram-pool` — принят.** Чисто, вся новая конфигурация вместе даёт 350–640 токенов
  префилла в секунду на контексте 25k и 27.8 токена decode — лучшие показания за всю историю.
- **`--expert-mma` — отвергнут.** Первое ядро проигрывает generic mmq на префилле (180–280
  против 350–640 токенов в секунду без него), а его округление на stream-k CUDA меняет ответы
  на длинной генерации (эхо-петли, свич языка, потеря контекста). Ядро остаётся в дереве как
  исследовательское, со своими паритет-тестами; живой возврат мыслим только с бит-точным
  режимом.
- **`--resident-topk` — отвергнут на DSv4:** веса маршрутизатора плоские (top-3 держат лишь
  65–67% веса экспертов токена), кап тупит модель. Клетки из свипа убраны.
- **STRATA_POLY_STAGED_TILES (env)** — оставлен в прод-наборе (`8,16,32`): decode-свип дал
  +9.3% внутри всего набора, но число ни разу не изолировалось против выключенного. Риск для
  ответов уже, чем читался первый вердикт: запуски размерных классов совпадают с однозапусчным
  путём до бита, кроме мест, где stream-k llama.cpp (split_exact) переставляет частичные суммы
  строки по числу тайлов запуска — перестановка fp32-сложения, не fp16-класс --expert-mma.
  Изолированный A/B (`knob_ab.sh --env STRATA_POLY_STAGED_TILES 8,16,32 off`) и батарея ответов
  на temperature 0 ещё впереди.
- **`--prefetch-k`** — не портирован: апстрим-серия сидит на чужих рефакторах; её работу
  забрал себе нативный пул `--ram-experts-mib`.

## Как пользоваться

Соберите движок на своём ПК, затем запустите сервер с нужными флагами, например:

```text
strata-poly --model deepseek-v4-flash-0731.gguf --kv q8_0 --read-overlap 1 --attend-batch 1
```

Чтобы сравнить версии, применяйте и откатывайте каждый патч через `git apply` / `git apply -R`.
Порядок поздних ядер не важен; патчи q8_0 и префилла должны оставаться первыми.
