# Гейты: длинный контекст и бюджет декода

Число публикуется только тогда, когда есть гейт, который его проверяет.  Пропускная способность —
это среднее по окну, которое включает префилл; регрессия, живущая только в цикле декода (лишний
запуск на слой, вернувшийся проход деквантизации), внутри него не видна.  А «окно выдано» — не то же
самое, что «окно работает»: движок может молча клампить, резать или неверно ставить строки, и на
коротких промптах это не заметно.

Два гейта, оба против **живого** сервера (конфиг: `host`/`port`/`api_key`) — их можно гонять и на
прода, ничего не поднимая:

```bash
./gates.sh                    # оба, с кодом возврата
./gates.sh budget             # только бюджет декода
./gates.sh needle             # только needle на длинном окне
```

## 1. Бюджет декода — `tools/decode_budget.py`

Два запроса с одним коротким промптом: `t(1 токен)` и `t(N токенов)`.  Разность, делённая на
`N-1`, — это steady-state:

```
ms/token = (t(N) - t(1)) / (N - 1)
```

Промпт короткий намеренно: число описывает цикл декода, а не кэш промпта.  Проваливается, когда
`ms/token` выше бюджета (`MS_TOKEN`, по умолчанию 60 мс ≈ 16 tok/s) или префилл ниже пола
(`FLOOR_PREFILL_TPS`).

## 2. Needle на длинном окне — `tools/ctx_needle.py`

В самое начало промпта, заполняющего запрошенное окно, кладётся уникальный служебный код
(`ZEBRA-XXXXXX`), в конце — вопрос о нём.  Ответ обязан содержать код: иначеattention через всю
длину не работает.  Строка проходит только если код найден **и** сервер действительно прочитал
≥90% запрошенных токенов (проверяется по `usage.prompt_tokens`, локально — своим токенизатором
движка).

Филлер нумеруется построчно (`Строка 000001. …`) — повторяющийся блок позволил бы ленивому пути
скопировать одну строку, и needle «прошёл» бы без всякой дальней связи.

```bash
ROWS="8192 32768" ./gates.sh needle
```

Окна по умолчанию — 8k и 32k: 128k на нашем префилле стоит десятки минут, это отдельный запуск.

**Пропуск считается провалом**: строка, которую нельзя построить (окно больше `max_context`
движка), печатает `SKIP` и валит гейт — иначе сводка читалась бы как «всё хорошо».

## Что гейты уже ловили бы

- молчаливый кламп окна (окно «выдано», но attention его не видит);
- регрессии KV-пути (park/restore, кольцо raw-строк, формат кэша);
- лишние запуски на слой в декоде (потерянная fused-квантизация, вернувшийся split-KV);
- деградацию префилла после правок в загрузчике/пуле.

## Связка с остальным

`bench_sweep.sh` меряет скорость вариантов и имеет свой префлайт (`WARM_CHECK`); гейты — отдельный
слой: их место в конце правки (или в CI), когда нужно подтвердить, что стало не только быстрее, но
и по-прежнему правильно.
